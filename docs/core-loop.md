# 领域模型

> 全项目最上层文档：系统里有什么、怎么运转。运转实现的权威定义见 design/runtime-architecture.md；调研素材（非权威）在 used-reference/。

## 系统是什么

一个配置驱动的多 LLM 模拟推演器：若干 LLM 扮演角色，在一张配置化流程图中自主推演；导演（用户）在局中以注入方式引导戏剧走向，在局间以调整配置方式迭代；推演全程以事件落盘，事件流向下游加工为复盘分析与视频素材。

## 存在物：四层

**服务层** —— 长期子系统。独立实现、独立持久化，不参与编排。
包括：Agent 服务（LLM 调用 + 身份牌 + 私有上下文）、记忆系统、黑板（跨组件数据面）、事件流（Script）、LLM 网关（多服务商接入 + 缓存 + 成本台账）。Agent 实例显式创建、显式销毁；不销毁则跨局存续，记忆长期积累。

**元组件层** —— 服务层的唯一调用面。
粒度如"调用 Agent-X""向 Agent 注入上下文""读写黑板""发射事件"。组件访问服务必须且只需经过元组件：服务实现全局唯一、行为统一可审计；元组件同时构成 AI 生成组件时的标准 API 面。

**组件层** —— 游戏逻辑的最小单元。
内部逻辑代码硬编码，以元组件为唯一能力来源；对外无返回值，只经黑板交换数据；事件落盘是组件自己的行为（内部调用发射元组件）。单个 Agent 的多步推理、多个 Agent 的交互，都是组件的内部设计，不是模型层级。

**编排层** —— 游戏流程的配置化表达。
流程图 = 组件节点 + 控制边（顺序 / 条件 / 并行 / 回边即循环），以 YAML 定义；条件是对黑板接口数据的声明式求值。新游戏规则 = 一张图 + 一组组件，不写新引擎。

内置组件之一值得单独点名：**导演门**——到达即挂起所在分支、等待导演输入，其余分支照常推进；输入经注入元组件进入指定 Agent 的私有上下文，让 LLM 以为那是自己的想法。导演门只是组件，不是层；必须显式放置，绝无全局自动生效。

## 运转：两个循环、一条工作流、一条管线

系统内两个嵌套的循环：

- **决策循环**（组件内部）：Agent 的多步感知、思考、交互。
- **游戏循环**（编排层）：一张流程图的完整执行。回合、阶段、幕都只是图的形状；多 Agent 并发 = 并行分支。裁判与参与者同构——裁判也是 Agent 服务实例 + 组件组合，只是身份牌与所用元组件不同。

系统外两条人的链路：

- **导演工作流**（迭代节奏）：开局（Bundle）→ 观察并在导演门干预 → 复盘 → 调整 Bundle 再开。导演是循环外的人，不是系统内的角色；系统的职责是让一切可配置、一切可归因，而不是把导演建模进循环。
- **产出管线**（下游加工）：事件流 → 复盘/高光提炼 → 文案分镜 → 素材合成 → 剪辑发布。加工者是任务处理 Agent，与局内模拟 Agent 不同类型，优先接入成熟 Agent 工具完成，不自研。

## 一局的生命周期

Bundle 加载（流程图 + 身份牌 + LLM 绑定 + 世界书 + 种子）→ 角色创建组件显式创建 Agent 实例 → 流程图执行，事件全量落盘，导演门可介入 → 局结束 → 未销毁的 Agent 可携带记忆进入下一局。

## 设计原则

1. **没有银弹**：不一切皆组件。跨流程、有独立生命周期的元素（记忆、上下文、LLM 接入）独立成服务，不套用组件范式。
2. **显式优于自动**：Agent 不显式销毁不关闭；导演干预不显式放置不生效；配置在外、逻辑在内。
3. **事件即事实**：一切状态变化落盘为事件，可重放、可归因、可分叉。
4. **规模纪律**：核心几千行内，唯一开发者通读无障碍；复杂度只许长在游戏规则（图 + 组件）里，不许长在框架里。
5. **新元素先定位**：任何新模块、新选型必须能定位到某一层的某一环；定位不了的，不做。
