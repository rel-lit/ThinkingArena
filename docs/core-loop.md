# 核心循环（Core Loop）

> 领域模型，全项目最上层文档。技术实现见 architecture.md，选型依据见 research.md。
> 原则：不试图用一个范式解决所有问题——跨流程的元素独立成服务，不套用组件范式。
> 任何模块与技术选型都必须能定位到某一环；定位不了的，不做。

## 四层模型

**服务层（非组件，独立系统）**

LLM/Agent 服务、记忆系统、上下文管理（黑板族）、提示词管理——按现代 Agent 设计规范各自独立实现，持久化。生命周期显式管理：角色创建组件调用 LLM 服务创建，角色删除组件调用释放并连锁清理其上下文；不显式删除则不自动关闭——Agent 服务可跨局存续，记忆长期积累。

**元组件层（规范化服务工具）**

服务层的唯一调用面，粒度如"调用 Agent-[name]"、"向 Agent 注入额外上下文"、"读写黑板"、"发射事件"。职责：让组件不各自重复实现服务访问；事件发射经此并做 schema 校验。按可对外暴露的统一规范实现——加 Adapter 即可供外部使用（MCP 等）；同时是 AI 生成组件时的标准 API 面。

**组件层（游戏流程节点）**

内部逻辑代码硬编码，以元组件为工具制作；无返回值概念，只经黑板交互；事件落盘是组件自己的行为（内部调用发射服务）。组件预期主要由 AI Agent 生成——元组件层是其创作边界。

**编排层（配置化 DAG）**

游戏流程 = 组件的有向图配置，支持顺序 / if / while / 并行分支；循环只是编排的一种形态。条件判别读取黑板继承服务所暴露的接口数据——组件的输入输出由编排层从黑板中提取。新游戏规则 = 一张图配置 + 组件组装，不写新引擎。

**导演组件（显式节点）**

一种特殊组件：流程中的输入门——等待导演输入并执行上下文注入（让 LLM 以为是自己的想法，改变思维惯性，类似断点调试中修改变量）。依赖该输入的分支阻塞，不依赖的分支照常推进。非全局自动生效，必须显式放置。

## 循环概念

- **决策循环**：组件的内部设计（多步感知/思考/交互），不是模型层级。
- **游戏循环**：编排层对一张图的完整执行。回合、阶段只是图的形状；多 Agent 并发 = 并行分支。
- **导演工作流**：人的节奏，非系统循环——开局（Bundle）→ 观察与节点干预 → 复盘 → 调 Bundle 再开。
- **产出管线**：事件流被加工为内容（提炼→文案/分镜→素材→合成→剪辑→发布）。加工者可含任务处理 Agent——与模拟 Agent 不同类型，优先经插件接入成熟 Agent 工具，不自研。

## 第一公民概念

- **局（Run）**：编排层一次图执行的全程。由 Bundle 定义、Script 记录，是导演工作流的迭代单元、产出管线的原料单元。
- **事件（Event）**：唯一事实源。一切皆事件，经统一发射服务落盘，可重放。
- **Agent 服务与身份牌**：身份牌定义"是谁"，LLM 绑定决定"用哪个脑子"；服务显式创建/释放，可跨局存续；记忆、上下文、提示词按其名下持久化管理。
- **黑板**：组件间唯一数据面；其继承服务暴露的接口是编排层条件判别的唯一读取对象。
- **组件与元组件**：游戏逻辑的全部载体与规范化服务工具，两者严格分层。
- **导演**：循环外的人。经导演组件注入，局间调整 Bundle，产出末端做剪辑裁决。

## 价值流

组件生产**行为**，编排生产**过程**，导演工作流生产**质量**，产出管线生产**内容**。
