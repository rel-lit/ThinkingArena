# 场景设计：异世界生存推演（代号 Odyssey）

> 来源：Vision 首个思维实验。原文构想——
> "一个人类被连续陆续丢到一大堆迥异的异世界，待不等的时间。如果能活下去（不落地即死）且没疯掉，是什么在起作用？假设这是一位刚毕业的博士研究生，如何选取其本科、硕士、博士三阶段的专业与课题（必须是中国或国外某所具体大学的具体专业 + 合理研究方向/课题），使其最大可能存活？通过裁判模拟推演，部分内容跑团化以支持更合理的推演。"

## 1. 复杂度评估与 MVP 裁剪

原构想有三个复杂源：**世界生成（开放式、迥异、数量不定）× 主角构建（真实大学专业/课题组合空间巨大）× 长线状态（跨世界存活与理智）**。三者同时做自由度过高，裁判 LLM 难以保持一致性。

裁剪策略（符合 roadmap Phase 3）：

| 维度 | 完整版 | MVP 版 |
|---|---|---|
| 世界 | LLM 生成器，数量不定 | **3 个手工编写世界**（设定可控、对比性强） |
| 主角 | 自由组合本/硕/博 | **1 个预设 Build**（配置文件中写死） |
| 判定 | 骰子 + 裁判 + 技能体系 | 骰子定档级 + 裁判叙事，技能仅作修正标签 |
| 局数 | 单局长线 | 单局 3 世界 × 5~8 回合 |

MVP 之后第一个扩展就是**锦标赛模式**（多 Build 并行跑同一世界序列）——它才是这个构想的视频爆点，但必须以单主角版跑通裁判逻辑为前提。

## 2. 游戏框架（跑团化部分）

### 角色与四层映射

按 core-loop.md 的四层模型定位：

- **Protagonist Agent**：主角。Agent 服务实例 + Build 身份卡（`identity_card_v1, kind=build`，见 design/identity-card.md）——本/硕/博院校专业 + 课题 + 派生技能标签与性格。
- **裁判**：不是单个角色，而是**组件组合**——Narrator 叙事组件（调 Agent 服务写情境与后果）+ Archivist 状态权威服务（维护结构化状态表、校验叙事不违背状态，防吃书）+ 骰子组件。
- **Director（你）**：通过导演组件 inject / whisper / edit_world 随时干预（architecture.md D2）。

### 状态表（Archivist 权威）

```yaml
protagonist:
  hp: 100            # 生理
  san: 100           # 理智，归零即"疯掉"，判负
  skills:            # 由 Build 派生，3~5 个标签 + 等级
    - { name: "野外生存", level: 2, source: "本科-中国地质大学(武汉)-地质学" }
  inventory: []      # 物资，跨世界可携带（有限制）
  mental_anchors: [] # 精神锚点：支撑 SAN 的信念/回忆，剧情中可建立或摧毁
world:
  id, day, env_tags, active_threats
timeline: []         # 事件史
```

### 流程结构（图编排）

一回合 = 流程图节点序列，每个节点是一个组件（组件内部硬编码逻辑，组件间由编排层配置化连接，支持条件与循环——见 architecture.md D7）：

1. **情境呈现**：Narrator 组件基于世界设定 + 状态表生成当前局面（含一个明确的压力源）。
2. **主角决策**：调 Protagonist Agent 服务，输出内心独白 + 行动声明（可声明使用技能/物资）。
3. **判定**：有明确成败属性的行动 → 骰子组件（d20 + 技能修正），档级：大成功/成功/部分成功/失败/大失败；骰点入 Script（骰运即素材）。
4. **后果结算**：Narrator 组件按骰级写叙事；Archivist 服务更新状态表（HP/SAN/物资/锚点变动，须给出数值依据）。
5. **理智检查**（条件分支）：SAN 大幅变动或遭遇认知冲击时触发；连续高压无"锚点"支撑会加速 SAN 流失——这是"什么在起作用"这一研究问题的机制化：**技能管活下去，锚点管不疯掉**。
6. **世界切换**（循环出口）：世界停留回合数由隐藏骰程决定（主角不知情）；切换时做一次"穿越冲击"判定；全部世界序列完成则退出回合循环。

### 胜负与产出

- 失败条件：HP≤0（死亡）或 SAN≤0（疯狂）。
- 通关条件：活过全部世界序列。
- 无论成败，Script（事件流）+ report.md 回答研究问题：哪些技能/锚点在关键时刻起了作用（由 report 任务处理 Agent 从事件史归因）。

## 3. Build 卡设计（候选示例，供讨论）

Build 必须落到真实院校专业 + 合理课题。示例两个极端路线：

**Build A：均衡生存流**
- 本科：中国地质大学（武汉）· 地质学（课题：野外地质填图）→ 野外生存、地质判读
- 硕士：北京协和医学院 · 急诊医学（课题：院前急救）→ 医疗处置
- 博士：中国科学院心理研究所 · 应用心理学（课题：极端环境心理韧性）→ SAN 维持、锚点构建

**Build B：技术死宅流（对照组）**
- 本科：清华大学 · 计算机科学与技术
- 硕士：MIT · EECS（课题：分布式系统）
- 博士：ETH Zürich · 机器人学（课题：SLAM）

Build B 在高科技世界碾压、在原始世界近似白板——这种反差正是裁判推演和视频的戏剧来源。**Build 卡即身份牌 YAML 文件**（Scenario Bundle 的 `identity_cards/` 目录），锦标赛模式就是一组 Build 卡并行。

## 4. 导演干预点（本场景的戏剧化抓手）

- `inject`：世界内突发事件（"商队路过""天象异变"），制造节奏拐点。
- `whisper`：给主角植入非理性冲动或虚假记忆（"你隐约记得这个世界的天空"），测试 SAN 系统韧性；走 prompt L8 深度注入，让 LLM 以为这是自己的想法。
- `edit_world`：中途调整威胁等级、延长/缩短停留时间。
- 跨局迭代：每局 report.md 指出平淡段落 → 调整世界设定或 Build 再演。

## 5. 视频化潜力（演绎分镜的天然结构）

- 世界切换 = 天然幕间转场；骰点大成功/大失败 = 高光帧；内心独白 vs 实际遭遇 = 解说双线。
- 研究问题本身即标题钩子："什么样的本硕博组合能在无限异世界活下来？"
